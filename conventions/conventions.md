# Conventions

- `conventions/purpose/convention.md`: every repo's purpose doc, three headings (what, why, goals), authored in prose (`repos/<repo-path>/purpose.md`), rendered into the repo as gitignored `assets/docs-agents/purpose.md`, included at the top of `AGENTS.md`, `CLAUDE.md`, `README.md`.
- `conventions/comments/convention.md`: comment label prefixes (`[where]`, `[why]`, `[what]`), `[>]`/`[<]` sectioning, 🤖 AI-generated marks.
- `conventions/makefile/convention.md`: house Makefile style, `[genai-include]` sectioning that feeds the generated Makefile doc for AI agents.
- `conventions/templates/convention.md`: repo docs generated with che templates from prose at the version in `PROSE_REF` (`@gitlab.com/konradodwrot/prose//<path>?ref=${{ env.PROSE_REF }}`, the value one `GRP_KO_VAR_PROSE_REF` group variable, seeded into `.env` locally). `AGENTS.md`, `CLAUDE.md` and intermediates gitignored, `README.md` and `LICENSE` rendered and tracked. `make render-templates`.
- `conventions/ci/convention.md`: lefthook pre-commit hooks (minimal: docs generation check), re-run in a minimal CI validate job.
- `conventions/ci-variables/convention.md`: every GitLab CI/CD variable carries a scope prefix, `GRP_<MNEMONIC>_VAR_` for group-level (`GRP_KO_VAR_` for `konradodwrot`), `REPO_VAR_` for project-level (the repo unnamed: the scope already names it). All declared in `infra/iac`, never clicked into the UI. Each pipeline remaps every injected variable it consumes to the bare name once, at the boundary (group vars in the top-level `variables:` block, project secrets on their job), and jobs, scripts and tools read only bare names. The bare name is never defined in GitLab. A tracked `.env.tpl` at the repo root, the one template che renders to `.env` (plain values, `{{ secret "op://..." }}`, `{{ shell "glab variable get ..." }}`), carries the same bare names for local runs.
- `conventions/dev-env/convention.md`: every repo exposes `repo-prepare-dev-env`, a wrapper chaining render, dependencies, then hooks (that order: the docsgen hook renders, so hooks installed before the first render fail a fresh clone's first commit). A repo declares its toolchain in a `devEnv` che profile rather than assuming the host carries it, and `repo-prepare-deps` installs that toolchain plus the project dependencies it manages, into the checkout and without root. `control`'s workspace profile runs it over every cloned repo, between cloning and indexing.
- `conventions/license/convention.md`: every public repo carries `LICENSE` (unmodified MIT), rendered from the canonical `prose/shared/license/LICENSE`.
- `conventions/spec-scenarios/convention.md`: behavior specs as markdown feature files, all in prose (`repos/<repo-path>/spec/`), edited there before implementing in the repo. Two forms sharing a stem in the unit dir: `<feature>.story.md` (user stories, the default: H2 `As a <role>`, H3 story title, `I want` / `so that`) and `<feature>.scenarios.md` (Gherkin scenarios, only for automation-bound behavior). Each story and scenario carries a `Status:` line (`todo | implemented | tested`) kept accurate, each title a value statement for its audience. Vetting dirs: `vetted/` (AI never touches), `vetted_title_only/` (story titles and `Scenario:` lines frozen, rest editable), `unvetted_ai/` (AI free rein, new AI specs land here). Moves between dirs come from human will. `technical-requirements.md` uses the same dirs, prefer `vetted/`: on add or change, AI urges vetting first.
- `conventions/claude-agents/convention.md`: per-repo `RO-<Repo>`/`RW-<Repo>` claude agents, che-rendered into `.claude/` on virt only. Shared snippets served from `configs` (authored in prose), consumed via one remote profile include plus `ctx`, rendered outputs never committed.

Each convention dir carries a runnable `example/`. This repo follows all of them.
