# Claude Agents Convention

Every workspace repo carries two claude agents in `<repo>/.claude/agents/`: `RO-<Repo>` (read-only scoping, planning, review, model fable) and `RW-<Repo>` (executor, model sonnet). On virt machines only, che renders `<repo>/.claude/settings.json` making `RW-<Repo>` the repo's default main-thread agent. Each repo owns only its `che.yml` wiring: one remote profile include of the shared `configs` profile. Every reference inside the profile stays local to `configs`. Rendered outputs never land in vcs.

## Naming

`RO-<Repo>` / `RW-<Repo>`, repo name PascalCase (`configs` → `Configs`, `infra/oci-images` → `OciImages`).

## Ownership Split

- `configs` owns the whole render: the `llm/claude/virt` profile in `profiles/llm/claude/che.yml` plus the snippets it renders, in `profiles/llm/claude/templates/snippets/`: `ro.md`, `rw.md` (full agent files: frontmatter + body, ctx `.repo` PascalCase), `settings.json` (`{"agent": "RW-{{ .repo }}"}`), `pwd.md` (invocation constraint, included by both agent snippets), `claude-gitignore`. The markdown snippets are authored in prose (`prose/repos/configs/ai/claude-snippets/`) and rendered into configs at its pinned prose version; dest options and intra-snippet includes stay local to `configs`. Dests target `${invokingSpecGitRoot}/.claude/...`.
- Each repo owns only its `che.yml` `claude-agents` profile: one remote profile include `@https://gitlab.com/konradodwrot/configs//profiles/llm/claude/che.yml::llm/claude/virt` with `ctx: {repo: <Repo>}`, the only per-repo content. No template files in the repo, no per-file remote refs.

A remote profile include goes through a real on-disk checkout of `configs` anchored at `profiles/llm/claude`, so `localFile` includes between snippets (e.g. `ro.md` pulling `pwd.md`) resolve inside the checkout, never against the consumer repo. Per-file remote template sources break there: `localFile` would resolve against the consumer, where the sibling snippet does not exist. The `@https://` scheme is required: profile checkout clones the URL verbatim. The include resolves from the configs default branch at render time: no sibling checkout needed, snippet changes apply once pushed to configs main. The repo path is never hardcoded: snippets inject it at render time from the rendering cwd (`env.Getenv "PWD"`), che renders from the repo root.

## Frontmatter

`name`, `description`, `model`, `permissionMode: bypassPermissions`, `memory: local` (memory dir `.claude/agent-memory-local/<name>/`, stays out of vcs). `tools` omitted: inherit all.

## Wiring

Each repo's `che.yml` carries one `claude-agents` profile, `options: {autoDiscover: true, runIf: ['builtin:isVirt']}`, whose only content is the remote profile include, rendered by that repo's `make render-templates`: on virt it renders, elsewhere it is skipped. Dest options live in the shared profile, not the consumer: agent and settings dests use `skipAutoGeneratedHeader: true` (the default overwrite prepends an autogen header, breaking frontmatter and JSON). The `.gitignore` dest keeps the default (the header is a valid gitignore comment). `settings.local.json` stays free for ad-hoc overrides.

## VCS Hygiene

Belt and suspenders: the global git ignore (`configs/root/HOME/.config/git/ignore`) ignores `**/.claude/settings.json`, `**/.claude/agents/{ro,rw}.md`, `**/.claude/agent-memory-local/` on all machines. The rendered per-repo `.claude/.gitignore` covers hosts without that global ignore.

## Example

`example/che.yml` is the consumer side: the `claude-agents` profile a repo carries, its entire footprint, one remote profile include. The shared profile and snippets live in `configs`, not here. On virt, `che render-templates` in the repo renders all four dests.
