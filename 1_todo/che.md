## execution

- che execution of multiple profiles MUST be treated as one unit, allowing for building a dependency graph

## templates rendering

- che template partial render type MUST exist to render part of a file marked by beginning and ending comment, retaining the rest of the file and injecting changed contents into the targeted file area
- che template partial render type MUST target a file with sectioned areas marked by opening comment `[>] <section>` and closing comment `[<] <section>`
- che template partial render type MAY target a file with nested sectioned areas
- che template using partial render type MUST target sections of a target file using the same sectioning comments
- che template using partial render type MAY contain multiple sections, for multiple areas to render

- che templates SHOULD be placed in .che/tpl directory
- che templates targeting repo tracked files SHOULD be placed in .che/tpl/repo-git-tracked directory
- che templates targeting repo untracked files SHOULD be placed in .che/tpl/repo-git-untracked directory
- che templates targeting hosts SHOULD be placed in .che/tpl/host directory

- che rendered file with auto generated header MUST NOT include ref
- it is RECOMMENDED that che rendered file includes autogenerated header with a source, without ref
- che rendered file MAY omit auto generated header, if it breaks consumer behavior of the file

## che files

- che MUST search repo root as well as .che directory for its files by default
- che MUST be able to read and understand files:

  ```
  <git-root>/
    che.yml
    che.env
    che.variables.yml
    .env
    .che/
      che.yml
      che.env
      che.variables.yml
  ```

- che files SHOULD be placed in:

  ```

    .env
    .che/
      che.yml

      che.variables.yml
  ```

- che templates SHOULD be placed in:

  ```
  <git-root>/
  ```

## Variables and Environment Variables

- default values for env variables spec use SHOULD be defined in che.env
- default values for variables spec use SHOULD be defined in che.variables.yml
- invoking spec MUST be able to set variables for included spec, when explicitly including profile or spec
- invoking spec MUST be able to include remote spec, including all profiles in it
- invoking spec MUST be able to include remote spec chosen profile
- invoking spec env vars MUST be able to include remote spec chosen profile

- included specs MUST include default value for an env variable, so invoking specs don't have to
- included specs MUST include default value for a variable, so invoking specs don't have to
- invoking spec MAY define env variable to be used by included specs
- che spec that uses environment variables SHOULD be accompanied by che.env with default values
- che spec that uses variables SHOULD define variables it uses upfront in top level `env:` block
- embedded che specs using remote references MUST consult che.env and `env:` of remote che spec for default values
- che MUST get env vars from: execution environment, che.env to assemble its environment
- che MUST NOT read env vars from .env file
- env vars MUST propagate through all remote specs, overriding default values of included specs
- variables MUST NOT propagate to remote specs, requiring explicit setting per spec or profile scope
- che templates MUST be able to parse env vars and variables
- che spec MUST be able to parse env vars and variables

## Remote References

- remote git sources MUST be cloned once per repository in a cache directory
- remote git sources MUST NOT include ref in directory path
- cloned remote git source MUST be reused across usages for rendering
- cloned remote git source MUST appear once in a cache
- using remote git source SHOULD be preceded by fetching refs, and this behavior MAY be disabled via option
- consulting remote git source for contents of files MUST happen in a worktree, to allow concurrent execution
- git worktree of remote git source MUST be created per ref in cache directory, and MUST be reused in repeated execution for that ref
- git worktree created for ref MUST be tracked in a che database
- git worktree created for ref MUST be removed after a configurable amount of time, counting from last use, defaulting to 4 weeks

## Installation

- binary installation method SHOULD install binaries into XDG_STATE_HOME into a directory designated for che installed binaries
- binary installation method SHOULD link binaries from XDG_STATE_HOME to a user preferred location
- binary installation method MUST consult XDG_STATE_HOME che bin directory to check if a particular version is already available, and if it is, reuse the binary and link it to the user preferred location
- che installation SHOULD track installation per package per version, and clear XDG_STATE_HOME for versions unused for a configurable amount of time, defaulting to 4 weeks

## Running Scripts

- che MUST provide a granular way to control script invocation per script using variables and environment variables, using names and regexps
