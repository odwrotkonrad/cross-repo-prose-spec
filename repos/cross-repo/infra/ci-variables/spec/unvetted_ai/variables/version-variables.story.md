# Feature: One Variable Per Artifact, One Value Per Consumer

<!-- [>] 🤖🤖 -->

A CI variable carries an artifact's version. It is transport, not a thing
produced or consumed, so it is not an artifact and holds no place in the graph.

Two scopes. The group variable is the producer's latest published version, set
by the producer alone. Each consumer holds its own project variable for each
artifact it consumes, which wins in that consumer's pipelines by GitLab
precedence. That is one variable per consumer-artifact pair, a large and
growing set, and intended: it is the only way a consumer can sit at a version
that is not latest, which is exactly what the desired and current graphs
measure.

Each artifact names its own variable, declared on the artifact rather than
derived from a naming convention. Two artifacts never share one: today
`ci-linux`, `ci-linux-dind` and `dev-sandbox` all ride `CI_IMAGES_REF` and
cannot move apart.

These variables live apart from `infra/iac`. Version refs move on every
release; identities and secrets almost never do.

One variable per consumer-artifact pair is too many to hand-maintain, and any
hand-kept list drifts from the graph as soon as a repo changes what it
consumes. So nothing here computes or enumerates them: automation generates the
tfvars from the graph and commits them, using a template this repo owns and
stores beside the modules that read it. Two modules receive them, one
group-scoped for producers and one project-scoped per consumer, each naming
every known variable as an optional input so an unknown one cannot pass.

## As a consumer repo owner

Reads versions from variables. Sets none of them.

### Sit at a version that is not the latest (todo)

I want my own project variable per consumed artifact, overriding the group
value,
so that lagging behind an upstream deliberately is expressible rather than
impossible.

### Read a variable name that says where it comes from (todo)

I want the name to carry a mnemonic of the producing repo and of the artifact,
so that reading it in a pipeline tells me who publishes it without consulting
the graph.

## As a producer repo owner

Publishes versions. Does not manage consumers' pins.

### Own the latest-version record for what I publish (todo)

I want the group variable for my artifact set from my own released version,
so that one place names the latest and nothing else claims to.

### Give each artifact its own variable (todo)

I want a variable per artifact, never shared with a sibling built beside it,
so that raising one version does not force the others' consumers to a tag
nothing changed in.

## As a workspace maintainer

Owns the variable declarations. Hand-lists none of them.

### Never hand-write a variable declaration (todo)

I want every tfvars file generated by automation from the graph and committed
here, from a template this repo owns taking a repo and its dependencies,
so that a set growing with every consumer-artifact pair costs no toil and
cannot drift from what the graph says.

### Keep the template beside what consumes it (todo)

I want the tfvars template stored in this repo rather than in automation,
so that the generated shape and the module reading it are edited together.

### Reject a variable no module declares (todo)

I want each module to name every known variable as an optional input, applied
only where a value is supplied, so a generated file naming an unknown variable
fails at plan,
so that a typo becomes a failed plan rather than a variable nothing reads.

### Plan one repo's variables without touching another's (todo)

I want a unit per consumer repo, planning and applying alone,
so that a regenerated file for one repo cannot surprise another, and one bad
generation blocks nothing else.

### Keep group and project scopes in separate modules (todo)

I want the producer module group-scoped and invoked once, the consumer module
project-scoped and invoked per repo,
so that two different scopes, prefixes and cardinalities are not forced through
one shape.

### Separate versions from identities (todo)

I want non-secret CI variables owned apart from tokens, keys and the group
tree,
so that a per-release change and a rarely-touched identity do not share an
apply.

### Name a variable once, prefix it at use (todo)

I want the artifact to carry the bare variable name, with each scope's prefix
applied only where it is read,
so that renaming is one edit rather than a coordinated sweep across scopes.

### Catch two artifacts claiming one variable (todo)

I want generation to fail when a variable name maps to more than one artifact,
so that the shared-variable bug cannot return unnoticed.
